## Задача

Приложение отображает портфолио проектов с фильтрацией по категориям
(`All`, `Websites`, `Flayers`, `Business Cards`). Клик по кнопке фильтра
обновляет список карточек без перезагрузки страницы.

## Разбор на подзадачи

1. `Portfolio` — классовый компонент с состоянием: хранит активный фильтр
   и отдаёт дочерним компонентам данные и обработчик.
2. `Toolbar` — функциональный компонент кнопок-фильтров: получает `filters`,
   `selected`, `onSelectFilter`, подсвечивает активный фильтр.
3. `ProjectList` — функциональный компонент сетки карточек: получает уже
   отфильтрованный массив `projects` и только рендерит его.
4. Данные и список фильтров вынесены в `src/data/projects.ts`.

## Структура

```
src/
  components/
    Portfolio.tsx    // классовый компонент, владелец состояния
    Toolbar.tsx      // кнопки фильтров (stateless)
    ProjectList.tsx  // сетка проектов (stateless)
  data/projects.ts   // данные из задания + список фильтров
  models.ts          // тип Project
  App.tsx
  App.css            // стили приложения
  index.css          // сброс и глобальные стили
```

## Нетривиальные решения

- **Состояние только в `Portfolio`** (принцип «поднятия состояния»): `Toolbar`
  сообщает о клике через callback `onSelectFilter`, а `ProjectList` получает
  готовый отфильтрованный массив. Дочерние компоненты состояния не имеют.
- **В `state` лежит только `selected`.** Список проектов неизменяем, поэтому
  копировать его в состояние незачем — это создало бы второй источник правды.
  Требование «`Portfolio` при инициализации содержит полный список проектов»
  выполняется: список импортируется в `Portfolio` и больше нигде не
  используется, владелец данных — он.
- **Фильтрация выполняется при рендере** в `getVisibleProjects()`, а не
  хранится в state, — иначе список пришлось бы синхронизировать с фильтром.
- **Порядок кнопок задан явно** через `CATEGORY_ORDER`, а не выводится из
  порядка проектов в данных: иначе первой категорией стала бы `Business Cards`
  и панель разошлась бы с макетом. Категории, которых нет в данных, всё равно
  не появятся.
- **У проектов есть `id`.** В исходном наборе `img` повторяется (`200.jpg`,
  `emi_haze.jpg`, `transmission.jpg`), поэтому URL не годится как `key`.
- **`base` не зашит в `vite.config.ts`** — workflow передаёт его флагом
  `--base=/<имя-репозитория>/`. Конфиг не нужно править при переименовании
  репозитория, а локальный `dev` работает от корня.

## Доступность

- Активность фильтра передаётся не только цветом: у кнопок есть `aria-pressed`,
  панель обёрнута в `role="group"` с подписью.
- Превью проектов декоративные, у них `alt=""` — иначе скринридер зачитал бы
  17 повторяющихся названий категорий.
- Видимый фокус на кнопках (`:focus-visible`), уважается
  `prefers-reduced-motion`.

## Стек

React 19, TypeScript 5.9, Vite 8, ESLint 9 (flat config) + Prettier.

ESLint оставлен на 9-й мажорной версии сознательно: `eslint-plugin-react` и
`eslint-plugin-jsx-a11y` пока не объявляют совместимость с ESLint 10.
TypeScript оставлен на 5.9 по той же причине — `typescript-eslint` 8.x
не поддерживает TS 7.

## Запуск

```bash
npm install
npm run dev
```

## Команды

| Команда                | Что делает                                 |
| ---------------------- | ------------------------------------------ |
| `npm run dev`          | Дев-сервер Vite                            |
| `npm run build`        | Проверка типов + продакшен-сборка в `dist` |
| `npm run preview`      | Локальный просмотр собранного `dist`       |
| `npm run typecheck`    | Только проверка типов                      |
| `npm run lint`         | ESLint                                     |
| `npm run lint:fix`     | ESLint с автоисправлением                  |
| `npm run format`       | Prettier — отформатировать                 |
| `npm run format:check` | Prettier — проверить без изменений         |

## Деплой

При пуше в `main` workflow `.github/workflows/deploy.yml` прогоняет линтер,
Prettier и проверку типов, затем собирает проект и публикует на GitHub Pages.

Перед первым пушем в настройках репозитория: **Settings → Pages → Build and
deployment → Source → GitHub Actions**.
